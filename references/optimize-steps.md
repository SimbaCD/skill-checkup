# 优化步骤

用户要求修改 Skill 时，按下面五步进行。结论里的"修改顺序"也按这个顺序排列。具体改法见 `references/checklist.md` 的"改法"一列，这里只规定先后。

## 第一步，先用真实任务运行一次

请用户给一个平时会交给这个 Skill 的真实任务，运行一次，记下没做好的地方：调用错了、步骤跳过了、规则没遵守、内容是编的。用户没有现成任务的，跳过这一步，以体检发现的问题为准。

## 第二步，对照四项定位原因

| 现象 | 多半出在 |
|---|---|
| 没有被调用，或调用了别的 Skill | 触发 |
| 参考文件没读，步骤被跳过，直奔成品 | 结构；引导中的完成标准 |
| 规则写得越多，遵守得越差 | 修剪；引导中的重复和叫法不一致 |
| 依赖的工具或信息不齐，就绕过或自行补全 | 引导中的工具配置、停顿点和校验 |

## 第三步，先做减法

执行 checklist 中属于删除和移动的改法：角色设定、通用知识、只在部分情形才用的内容、写给维护者的内容、重复的规则和文件。拿不准能不能删的，删去后用第一步的任务再运行一次，行为没有变化就删。

## 第四步，再补关键内容

执行 checklist 中属于补充的改法，顺序是描述、主文件前部的必守规则、指引条件、完成标准和停顿点、校验环节。

## 第五步，复查

1. 重新运行扫描脚本（`python <本 Skill 的文件夹>/scripts/scan.py <Skill 文件夹>`），确认机械检查项已经消除。
2. 用第一步的任务再运行一次，确认问题已经消失。
3. 提醒用户在自己常用的 Agent 和模型上各试一次；以后更换主力模型时，对教模型做事的部分（生成特定格式、调用某个接口）重新做一次删除测试，记录用户自己做法的部分（习惯、口径、文风）保留。
